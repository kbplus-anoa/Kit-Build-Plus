# ui-share — 为什么
为什么引入这个功能。说不清就先别做。

## 问题

`rebuild` 与 `score` 都要画概念图。按"feature 之间禁止 import"的约定，
就得在两个 feature 里各写一份画布——两份实现迟早分叉，
而分叉的后果是"学生看到的图"与"报告里的图"长得不一样，学生无法对照。

## 目标

把"怎么画"抽出来共享：图元、画布交互、页面骨架、样式令牌。
两个 feature 都能 import 它，这是它存在的理由。

## 不做什么

不含业务逻辑、不判断对错、不碰数据库、不引用 contract-share 的业务类型。
一旦组件要知道"这条命题对不对"，它就该待在对应 feature 里。

## 当前状态

**未实现。** 前端尚未开工，本目录目前只有边界与命名约定。
