# extract — 设计
用户体验/页面设计

## 页面与交互
> 总是遵循本·施奈德曼（Ben Shneiderman）的界面设计八条黄金法则，且须全部达成。
> 与用户讨论方案阶段须说明为何达到了这八条

本 feature 是**后台过程**，学生看不到。它唯一的界面是给教师侧的"抽取结果预览"，
嵌在 `kit` 的裁定页里，不单独成页。逐条对照：

1. **保持一致性**：候选三元组在所有教材、所有学科都用同一种列表行
   （概念A —连接词→ 概念B + 置信度），不因词表不同改版式。
2. **允许熟练用户走捷径**：整批接受 / 整批驳回的批量按钮常驻；
   教师不必逐条点 200 次才能清空一批噪声。
3. **提供有信息量的反馈**：抽取超过 5 秒显示"已处理 3/12 段"，
   并说明卡在哪一段，而不是无信息等待。
4. **把对话设计成结束**：抽完给出结论"得到 37 条候选，其中 26 条连接词集中在『属于』"，
   并直接给"进入裁定"按钮。
5. **防止错误**：词表为空、连接词重复、超量时**在点抽取前**就拒绝，
   而非等模型跑完才报"词表非法"。
6. **允许轻松撤销**：重抽不覆盖上一批，两批并列存放（D23 重抽并存），
   教师可切回旧批再裁定。
7. **保持内部对话记忆**：裁定页顶部常驻"本批次来自《教材名》第 N 次抽取，
   词表 心理学 v1"，教师不必回头确认抽的是哪份。
8. **减少短期记忆负担**：低置信度条目**不用颜色深浅**表达，
   直接用数字（0.41）与文字（"低"）标出，并给出阈值说明。

## 数据流

```
纯文本 ──window.split──> 若干段（480 字，重叠 80）
   │
   ├─ 每段按 schema {"概念": [连接词...]} 送 ONNX UIE
   │      └─ 模型的输出值域被 schema 锁死 ⇒ 越界不可能
   │
   └─ raw_to_triples（丢弃越界）→ merge_key 去重 → 按置信度降序
                                   │
                                   v
                        ExtractionResult（契约）
```

契约出口：`contract-share/triple.py` 的 `ExtractionResult`。

## 无障碍功能
> 含且只含：
> 1. 色盲
> 2. 计算机使用不熟练者

- **色盲**：候选条目的"接受/驳回"状态不用绿/红，用 ✓（已接受）与 ✕（已驳回）
  两种**形状不同**的符号，且文字标签始终可见。
- **计算机使用不熟练者**：批量按钮写成"全部接受本页 20 条"，
  写清范围与数量，避免误点全库；重抽入口旁常驻一句
  "重抽不会删除上一次的结果"。
