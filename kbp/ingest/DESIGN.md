# ingest — 设计
用户体验/页面设计

## 页面与交互
> 总是遵循本·施奈德曼（Ben Shneiderman）的界面设计八条黄金法则，且须全部达成。
> 与用户讨论方案阶段须说明为何达到了这八条

本 feature 无独立页面，只提供上传入口给 `kit` 的准备页。逐条对照：

1. **保持一致性**：上传控件在教材准备页只有一个位置、一套措辞；
   三种格式共用同一上传按钮，不按格式换界面。
2. **允许熟练用户走捷径**：拖拽文件到上传区即触发，不必先点按钮再选文件。
3. **提供有信息量的反馈**：解析中的进度按阶段显示"判定格式 → 提取文本 → 云解析"，
   而不是只有一个转圈。
4. **把对话设计成结束**：解析完成即给出一句结论"已得到 18 页、47109 字，含文字层"，
   并给下一步按钮，不留悬空状态。
5. **防止错误**：上传前按魔数校验格式，选错文件当场说明，不进入解析。
6. **允许轻松撤销**：解析结果可弃用重传，缓存不覆盖旧记录。
7. **保持内部对话记忆**：再次进入时显示上次解析的文件名与结论，不必重新上传。
8. **减少短期记忆负担**：失败提示写"未配置 MINERU_TOKEN，扫描件无法解析"，
   直接说清要做什么，不要求用户记住错误码。

## 数据流

```
文件路径 → detect.sniff（魔数优先）
  ├ txt  → textfile.read_text（UTF-8 → GB18030 回退）
  ├ epub → epub.read_epub（zip 内 html 拼接 + 剥标签）
  └ pdf  → pdf.read_pdf
             ├ 文字层够密 → TextDoc(source=TEXT_LAYER, has_ocr=False)
             └ 稀疏       → ocr.upload_and_parse → TextDoc(source=OCR_CLOUD, has_ocr=True)
```

契约出口：`kbp/contracts/textdoc.py` 的 `TextDoc`。

## 无障碍功能
> 含且只含：
> 1. 色盲
> 2. 计算机使用不熟练者

- **色盲**：解析状态不用红/绿区分，一律"文字 + 图标形状"（✓ 完成 / ↻ 处理中 / ! 失败）。
- **计算机使用不熟练者**：上传按钮文字为"选择教材文件"，旁边常驻一句
  "支持 txt、epub、PDF；扫描版会自动送云端识别"，不依赖悬停提示。
