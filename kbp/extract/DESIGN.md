# extract — 设计
用户体验/页面设计

## 页面与交互
> 总是遵循本·施奈德曼（Ben Shneiderman）的界面设计八条黄金法则，且须全部达成。
> 与用户讨论方案阶段须说明为何达到了这八条

本 feature 是**后台过程**。它出现在两处：学生端的"教材准备"（自动裁 kit 前一步），
与开发期的"抽取结果预览"（嵌在 kit 裁定页里）。逐条对照：

1. **保持一致性**：同一份教材无论抽几次、在哪台机器上抽，都用同一套展示形态
   （主语 —连接词→ 宾语 + 依据原文片段），不因模型或词表换版式。
2. **允许熟练用户走捷径**：配置一次密钥后全局复用，不必每次输入；
   提供"只抽这一章"的入口，不必整本跑一遍。
3. **提供有信息量的反馈**：调用期间显示"正在请求模型（第 2/3 段）"，
   而不是一个无信息转圈；失败时说明是哪一类失败。
4. **把对话设计成结束**：抽完给一句结论"得到 27 条命题，覆盖 19 个概念"，
   并给"生成 kit"这一个明确的下一步。
5. **防止错误**：未配置密钥时**在点击前**就提示"需要先在设置里填 API 密钥"，
   而不是点了才报错；正文超长时先告知会截断到多少字。
6. **允许轻松撤销**：重抽不覆盖上一批，两批并列；旧批可切回再审。
7. **保持内部对话记忆**：顶部常驻"教材名 / 词表版本 / 模型名 / 抽取时间"，
   不必回头确认这批是用什么配置抽的。
8. **减少短期记忆负担**：每条命题带**依据原文片段**（evidence），
   用户不必在正文里自己找它来自哪一句。

## 数据流

```
纯文本 + 词表 + ExtractConfig
      │
      ├─ window.split：按空行分段，超长段按字上限硬切
      │
      ├─ prompt.build：词表 + 原文 → 系统提示与用户提示
      │     （JSON Output 要求提示里含 json 字样并给出样例）
      │
      ├─ chat_client.chat：httpx 直调 OpenAI 兼容接口
      │     │  Bearer 密钥从 KBP_API_KEY 读（协议只有一套，不写死服务商）
      │     └─ 失败重试最多 2 次（空 content 与限流/5xx）
      │
      └─ normalize.to_candidates：模型 JSON → 契约三元组
            ├─ 越界连接词 → 丢弃
            ├─ 自环 → 丢弃
            ├─ 重复 → 丢弃
            ├─ 概念里塞了词表连接词 → 丢弃（最硬的确定性信号）
            ├─ 概念超过 20 字 → 不丢，置 suspect 并排到最后
            ├─ evidence 缺失 → 退回首句（无原文则空串，不阻断）
            └─ 置信度 = 本地代理分：evidence 逐字命中得 1.0，对不上 0.4，
               没证据 0.2；越序乘 0.6；suspect 封顶 0.15。
               同分按首次出现顺序 → 同一输入两次输出同序
                          │
                          v
              ExtractionResult（契约）→ record → ExtractionRecord（留档）
```

**协议是 OpenAI 兼容格式，供应商只是配置。** provider 只有一个值
`openai_compatible`（界面上叫「自定义 / OpenAI 兼容」），换服务商只改
`base_url`、`model` 与密钥环境变量 `KBP_API_KEY`，代码不动。
开发期样例是 DeepSeek（`https://api.deepseek.com` + `deepseek-chat`），
因为价格与中文表现都合适；配置默认留空，由用户填自己的服务商。

**密钥绝不出现在**：日志、异常信息、配置结构、HTTP 响应。只从环境变量读取。

**为什么不用模型自报的 confidence**：实测常整列缺省或恒为 1.0，不同服务商之间也不可比。改成按「证据能不能在原文里逐字找到、位置对不对」本地算分，同一输入可复现，排序稳定；分数只决定先看哪条，不决定丢不丢。

契约出口：`kbp/contracts/triple.py` 的 `ExtractionResult`；
配置：`kbp/contracts/extractconfig.py`；
档案：`kbp/contracts/extraction.py`。

## 无障碍功能
> 含且只含：
> 1. 色盲
> 2. 计算机使用不熟练者

- **色盲**：命题行状态不用红/绿，用 ✓ / ✕ 两种形状 + 文字；
  置信度用数字而非色阶。
- **计算机使用不熟练者**：密钥填写框旁常驻一句"在你的服务商 API Keys 页面创建，
  粘贴后保存即可"（开发期样例直接写 DeepSeek 官网路径）；
  错误提示写人话（"密钥无效，请检查是否复制完整"），不暴露状态码与英文原文。
