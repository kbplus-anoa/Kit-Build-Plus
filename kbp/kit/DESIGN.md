# kit — 设计
用户体验/页面设计

## 页面与交互
> 总是遵循本·施奈德曼（Ben Shneiderman）的界面设计八条黄金法则，且须全部达成。
> 与用户讨论方案阶段须说明为何达到了这八条

**本 feature 有两条路，界面完全不同：**

- **运行期自动路**：无界面，学生点"开始"后由机器完成，只显示进度与结果
- **开发期人工路**：裁定页，逐条接受/驳回，用于产出标注

### 运行期自动路（学生可见的部分）

1. **保持一致性**：无论哪份教材，自动裁 kit 都是同一个按钮、同一段等待文案。
2. **允许熟练用户走捷径**：已裁过的教材可缓存复用，不必每次重抽。
3. **提供有信息量的反馈**：显示"正在读教材 → 正在抽取 → 正在生成零件集"三段，
   而不是一个转圈。
4. **把对话设计成结束**：裁完给一句结论"生成 24 条命题、19 个概念、5 个连接词"，
   并给"开始建图"下一步。
5. **防止错误**：未配置密钥、教材为空、抽取结果为空时，**在开始前**就拦下并说明。
6. **允许轻松撤销**：重新裁会生成新版本，旧版本若有学生用过则锁定不可覆盖。
7. **保持内部对话记忆**：顶部常驻"教材名 / 词表 / 模型 / 版本 / 指纹前 8 位"。
8. **减少短期记忆负担**：不用解释什么是"命题"——直接说"你的零件是 19 个概念和 5 个词"。

### 开发期人工路（裁定页）

1. **保持一致性**：接受/驳回按钮位置固定；冻结按钮只在右下角出现一次。
2. **允许熟练用户走捷径**：键盘 `A` 接受、`R` 驳回、`J/K` 移动、`Enter` 下一条；
   批量"本页全接受 / 全驳回"。
3. **提供有信息量的反馈**：顶部进度"已裁定 37/58，接受 29，驳回 8"。
4. **把对话设计成结束**：冻结后显示目标图缩略 + 零件数 + 指纹。
5. **防止错误**：冻结前二次确认，点明"学生将看到的评分标准就是它，冻结后不可改"。
6. **允许轻松撤销**：冻结前任意改判；冻结后只能新建版本。
7. **保持内部对话记忆**：顶栏常驻教材名 / 批次 / 词表版本 / 当前版本。
8. **减少短期记忆负担**：每条候选带**依据原文片段**，不必回正文里找。

## 数据流

```
【运行期】ExtractionResult（契约）
   └─ freeze_auto(result, map_version) ──┐
                                          ├─ 共用规则：概念按字面去重并按首次出现编号
【开发期】AdjudicationLog（契约）          │           命题去重、去自环
   └─ freeze(log, map_version) ───────────┘           计算内容指纹
                                          │
                                          v
                                    TargetMap（契约）
                                          └─ split ──> Kit（概念集 + 连接词集）
```

**两条路必须共用同一套冻结规则。** 若各写一套，开发期评估的人工图
与运行期自动图会不一致，评估结论就不能迁移。
规则与指纹都在 `kbp/kit/_rules.py`；
测试 `test_两条路对同一组命题给出相同指纹` 把这条钉住。

契约出口：`kbp/contracts/targetmap.py` 的 `TargetMap` / `Kit`；
`kbp/contracts/adjudication.py` 的 `AdjudicationLog`。

## 无障碍功能
> 含且只含：
> 1. 色盲
> 2. 计算机使用不熟练者

- **色盲**：接受/驳回不用绿红，用 ✓ 与 ✕ 两种不同形状；已裁定行用实心/空心方块。
- **计算机使用不熟练者**：每个按钮带主谓宾说明（"冻结目标图 —— 此后学生看到的
  评分标准就是它"）；危险动作用文字确认框；页面顶部给一行"这一步在做什么"。
