# api（原 src/）— 为什么
为什么引入这个功能。说不清就先别做。

## 问题

各 feature 分别可测，但**没有一个能跑的入口**：学生与研究者只能用测试驱动。

更麻烦的是装配：约定禁止 feature 互相 import，但"谁把它们拼起来"没有归属。
此前靠 8 份 `test/conftest.py` 与 5 处 `install_paths()` 拼 `sys.path`，
后果已经撞了两次——`service.py` 撞名、`quiz.py` 与目录撞名，
每次都表现为"测试拿到了别的 feature 的模块"，极难定位。

## 目标

- 一个 HTTP 入口，把已有 feature 暴露成可调用接口
- 装配集中在一处：哪些表进同一个库、谁注入给谁
- **不再需要任何 `sys.path` 拼装**：改为单一包 `kbp/`，模块名天然带命名空间
- 参数与错误在边界收口：feature 抛的领域异常映射成合适的状态码
- 密钥只从环境变量读，接口只回显"是否已配置"

## 不做什么

不含业务规则、不直接写 SQL、不渲染页面。前端在根目录 `web/`，页面设计由用户提供。
