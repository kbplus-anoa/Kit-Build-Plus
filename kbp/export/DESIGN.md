# export — 设计
用户体验/页面设计

## 页面与交互
> 总是遵循本·施奈德曼（Ben Shneiderman）的界面设计八条黄金法则，且须全部达成。
> 与用户讨论方案阶段须说明为何达到了这八条

**导出页**面向研究者，不是学生。一页完成"选记录 → 下载"。逐条对照：

1. **保持一致性**：下载按钮永远在同一位置、同一措辞（"导出被试级 CSV"），
   不因筛选条件变化而换措辞。
2. **允许熟练用户走捷径**：默认全选；支持按被试、教材、时点一键筛选后导出。
3. **提供有信息量的反馈**：下载完成后提示文件名，而不是静默开始下载。
4. **把对话设计成结束**：下载完成给一句明确结论"已导出 subject_2026-10-25.csv"，
   并给"继续导出"这个下一步。
5. **防止错误**：库里没有符合条件的记录时只提示"没有符合条件的记录"，不给空文件。
6. **允许轻松撤销**：导出只读不改数据，重复导出无副作用。
7. **保持内部对话记忆**：筛选条件留在页面上，返回再进不必重选。
8. **减少短期记忆负担**：表旁常驻一句列数说明（"被试级 22 列，含四类错误计数与抽崩信号原值"）。

## 数据流

```
score 结果（上游，**不重算**）
   │
   └─ SubjectRow[] ──> subject_table.build ──> csv_writer.to_csv
                                                  ├─ BOM 前缀
                                                  ├─ 固定 8 位小数
                                                  └─ 列宽校验
                                                        └─> subject.csv
```

契约出口：`kbp/contracts/exportcsv.py` 的 `SubjectRow` / `CsvPayload`。编码固定 `UTF8_BOM`。

## 无障碍功能
> 含且只含：
> 1. 色盲
> 2. 计算机使用不熟练者

- **色盲**：导出成功/失败不用绿红，用 ✓ 与 ! 两种字符 + 文字说明；
  可选记录状态用复选框形状表达，不依赖高亮色。
- **计算机使用不熟练者**：每个按钮写明范围（"导出全部 24 条"）；
  下载完成提示里给出**文件的完整路径**，不要求用户去下载文件夹里找；
  不出现"编码 utf-8-sig"之类术语，改写"Excel 可直接打开，中文不乱码"。
