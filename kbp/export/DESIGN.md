# export — 设计
用户体验/页面设计

## 页面与交互
> 总是遵循本·施奈德曼（Ben Shneiderman）的界面设计八条黄金法则，且须全部达成。
> 与用户讨论方案阶段须说明为何达到了这八条

**导出页**面向研究者，不是学生。一页完成"选记录 → 选表 → 下载"。逐条对照：

1. **保持一致性**：两张表的下载按钮永远在同一位置、同一措辞
   （"下载被试级 CSV / 下载题级 CSV"），不因筛选条件变化而换措辞。
2. **允许熟练用户走捷径**：默认全选；支持按教材、场次、组别一键筛选后导出；
   记住上次的筛选条件。
3. **提供有信息量的反馈**：选完先显示"将导出 24 条被试记录、480 行题级记录"，
   下载完成后提示文件名与字节数，而不是静默开始下载。
4. **把对话设计成结束**：下载完成给一句明确结论"已导出 subject_2026-10-25.csv，
   24 行，UTF-8 带 BOM"，并给"打开文件夹 / 继续导出另一张表"两个下一步。
5. **防止错误**：空选时按钮禁用并说明"请至少选择一条记录"；
   列出会因枚举越界而失败的记录，**在导出前**指出，而不是给一个坏文件。
6. **允许轻松撤销**：导出只读不改数据，重复导出无副作用；
   若上次导出的筛选与本次不同，提示"筛选已变更，本次将导出 18 条（上次 24 条）"。
7. **保持内部对话记忆**：页面保留最近几次导出记录（时间、表类型、行数、筛选），
   研究者能确认"昨天导的是哪一批"。
8. **减少短期记忆负担**：每张表旁常驻一句列数说明与关键列提示
   （"被试级 22 列，含四类错误计数与抽崩信号原值"），不必去翻 CSV_PLAN。

## 数据流

```
score 结果 / quiz 作答（上游，**不重算**）
   │
   ├─ SubjectRow[] ──> subject_table.build ──┐
   └─ QuestionRow[] ──> question_table.build ─┤
                                              ├─> csv_writer.to_csv
                                              │       ├─ BOM 前缀
                                              │       ├─ 固定 8 位小数
                                              │       └─ 列宽校验
                                              v
                                   subject.csv / question.csv
```

契约出口：`kbp/contracts/exportcsv.py` 的 `SubjectRow` / `QuestionRow` /
`CsvPayload`。编码固定 `UTF8_BOM`。

## 无障碍功能
> 含且只含：
> 1. 色盲
> 2. 计算机使用不熟练者

- **色盲**：导出成功/失败不用绿红，用 ✓ 与 ! 两种字符 + 文字说明；
  可选记录状态用复选框形状表达，不依赖高亮色。
- **计算机使用不熟练者**：每个按钮写明范围（"导出全部 24 条"）；
  下载完成提示里给出**文件的完整路径**，不要求用户去下载文件夹里找；
  不出现"编码 utf-8-sig"之类术语，改写"Excel 可直接打开，中文不乱码"。
