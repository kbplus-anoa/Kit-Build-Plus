# export — 索引
职责：CSV 导出（单/多/全选）。**不重新算分**，只读上游结果。

| 文件 | 内容 |
|---|---|
| `csv_writer.py` | `to_csv`：UTF-8 带 BOM；`quote` 统一空值/布尔/小数（固定 8 位）；`check_width` 防列错位 |
| `subject_table.py` | 被试级表 22 列（CSV_PLAN A–F 节）；关联键四元；越界枚举、分子超过分母一律拒绝；`fms` 列量纲 0~100 |
| `question_table.py` | 题级表 10 列（CSV_PLAN H 节），long 格式；关联键与题干列并排 |
| `tests/export/` | BOM、列宽、分子分母校验、中文列名、端到端落盘 |

## 为什么要带 fingerprint 列

同一教材在不同机器上自动裁 kit，可能得到不同概念与命题，但版本号都叫 `v1`。
少了指纹这一列，导出的数据没法筛"同一批人"，跨机器的分数会被错误地混在一起算。
导出层只搬运这个值，不参与计算。

## 为什么分数在这里现算却不违规

SPEC 说"export 不重新算分"。这里的分**只是 `correct/total` 的一次除法**，
分子分母都来自上游；不另存一份分数、不重做命题匹配。
真正的风险是"导出分数"与"屏幕分数"不一致——只要两边都从同一对分子分母除，
就不可能不一致，而导出层若自己跑一遍 `score` 才会出问题。

## 编码为什么必须带 BOM

Excel for Windows 不带 BOM 时会按本地 ANSI 猜编码，中文列名与概念名全乱码。
代价是部分 Linux 工具会把 BOM 当内容，读取时需容忍。
