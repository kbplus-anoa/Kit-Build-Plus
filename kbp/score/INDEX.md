# score — 索引
职责：命题级查表、四类错误、报告。不做图匹配、不改目标图。

| 文件 | 内容 |
|---|---|
| `lookup.py` | 查表核心：`target_keys` / `submitted_keys` / `count_correct` / `unmatched` / `missing` |
| `classify.py` | 四类错误链，判定顺序固定：reversed → leaving → excessive → lacking |
| `score_service.py` | `score(target, sub)` 出 `ScoreResult`；`ratio` 算分；`summary` 出计数摘要 |
| `tests/score/` | 全对满分、空卷零分、四类互斥、错误不影响分数、全链路端到端 |

## 为什么是查表不是图匹配

kit 封闭 ⇒ 学生提交的每条命题要么在目标图里、要么不在。
所以评分是 **O(E) 查表**，不是 GED（SPEC 已明确不做图编辑距离）。

## 判定顺序为什么固定

同一条错写可能被多种方式解读。例：目标图有 `c1-包括->c2`，
学生写 `c2-包括->c1`——这既是"目标里没有"，也是"方向反了"。

顺序安排为 **最具体 → 最泛化**：

1. `reversed`：反向命题存在，方向错
2. `leaving`：两端概念在目标图成对出现，只是连接词不对
3. `excessive`：概念对或连接词在目标图里完全找不到
4. `lacking`：目标图有、学生没写

每一类都先排除更具体的类别，**保证一条错写只归一类**——否则报告里
同一处错误会显示两次，学生不知道改哪个。

## 边界（已定：方案 1）

错误链**只带原始三元组**，不带"正确答案参考"、不带置信度。
报告里的解释话术由界面拼装，评分类只输出事实。
