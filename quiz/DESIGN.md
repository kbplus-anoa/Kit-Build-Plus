# quiz — 设计
用户体验/页面设计

## 页面与交互
> 总是遵循本·施奈德曼（Ben Shneiderman）的界面设计八条黄金法则，且须全部达成。
> 与用户讨论方案阶段须说明为何达到了这八条

**测验页**出现在三个时点（前测 / 后测 / 延迟后测），三处复用同一个组件。
题量一屏一题，不做长表单。逐条对照：

1. **保持一致性**：前测、后测、延迟后测**同卷同版式**（D30），
   只改顶部一行"这是第几次测验"，不换布局、不换按钮措辞。
2. **允许熟练用户走捷径**：单选题数字键 `1–4` 直接作答并进入下一题；
   可选"快速模式"隐藏进度与说明，只留题干与选项。
3. **提供有信息量的反馈**：底部进度写"第 7 / 20 题，已答 7 题"；
   **作答过程中不给对错反馈**（那是成绩，不是练习）。
4. **把对话设计成结束**：最后一题答完即给总结页"20 题全部作答，可以提交"，
   提交后给一句"作答已记录"，并说明"结果由研究者汇总，本页不显示分数"。
5. **防止错误**：未答题目在提交前列成清单，允许回去补；
   提交二次确认写明"共 20 题，你还有 2 题未作答，未作答按错误计分"。
6. **允许轻松撤销**：提交前随时改选；提交后不可改（成绩已入档），
   界面在提交前就把这条讲清，不在提交后才说。
7. **保持内部对话记忆**：中途断线重进时恢复已答题目并提示
   "已恢复上次作答（7 题）"；顶部常驻"第几次测验 / 共几题"。
8. **减少短期记忆负担**：题干区不出现跨题依赖；选项顺序固定（同卷可比），
   不在三次施测间随机打乱。

## 数据流

```
Question[]（同卷保存一次，quiz_set 表，不可被改写）
   │
   └─ 每次施测：Answer[] + time_point
          └─ 判对（grade.is_correct：未作答 = 错）
                └─ 逐题写 answer 表（含 is_correct）
                      └─ 百分制 = 答对数 / 题数 × 100
```

契约出口：`contract-share/quizsheet.py` 的 `Question` / `Answer` / `QuizRecord`。
题级 CSV 的十列由 `export` 从本层取。

## 无障碍功能
> 含且只含：
> 1. 色盲
> 2. 计算机使用不熟练者

- **色盲**：已答/未答不用颜色区分，用**圆圈填实 / 空心** + 底部计数文字；
  选中项用**加粗边框 + 前置实心圆点**，不依赖高亮色。
- **计算机使用不熟练者**：一屏一题、单列大按钮，不用分栏或横排小选项；
  题干下方常驻一句"选一个答案，选完自动进入下一题"；
  支持键盘与鼠标两条路径且都在页面上写明；不做计时倒计时。
