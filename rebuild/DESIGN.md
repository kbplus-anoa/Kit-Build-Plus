# rebuild — 设计
用户体验/页面设计

## 页面与交互
> 总是遵循本·施奈德曼（Ben Shneiderman）的界面设计八条黄金法则，且须全部达成。
> 与用户讨论方案阶段须说明为何达到了这八条

**重建页**是学生唯一的操作面，也是全线最需要打磨的一页。
一块画布、左侧零件栏、底部操作条，**任何位置都不出现对错提示**。逐条对照：

1. **保持一致性**：概念块与连线在所有题型、所有教材里同款渲染；
   "保存草稿 / 提交"固定在底部操作条同一位置，不随画布缩放移动。
2. **允许熟练用户走捷径**：鼠标可拖拽连线，**触摸屏可点-点连线**
   （ReactFlow `connectOnClick`，handle 至少 24px 命中区）；
   `Ctrl+S` 存草稿、`Ctrl+Enter` 提交。
3. **提供有信息量的反馈**：零件栏实时显示"已用 7/24 个概念、3/6 种连接词"，
   保存后显示"已保存 14:32"，让"我的东西还在"这件事可见。
4. **把对话设计成结束**：提交前弹确认，列出"你连了 12 条命题，用了 9 个概念"，
   并明确下一步"提交后进入评分"；**测验模式另加一句"提交后不可修改"**。
5. **防止错误**：只允许用 kit 内零件 —— 画布不接受自由输入；
   自环、重复连线即时拒绝并说明"这条已经连过了"；离开页面前若有未保存改动，
   拦截并提示先存草稿。
6. **允许轻松撤销**：`Ctrl+Z` 撤销、`Delete` 删除选中元素；
   **学习模式**提交后仍可返回继续改（循环至一致）；
   **测验模式**提交后锁定，界面把"锁定"写在按钮旁而不是事后报错。
7. **保持内部对话记忆**：进入页面自动续做上次草稿，顶部显示
   "上次保存 14:32 · 草稿已恢复"；不限时，不显示倒计时（避免人为焦虑），
   但在实验场景按 SPEC 由平台侧 35–40 分钟自动提交。
8. **减少短期记忆负担**：零件栏按"已用/未用"分组可折叠；
   连线时把当前选中概念高亮；不要求学生记住目标图长什么样。

## 数据流

```
Kit（契约：概念集 + 连接词集，无连接）
   │
   ├─ 拖拽/点选连线 ──> SubmittedProposition[]（只能用 kit 内零件）
   │        └─ 校验：越界概念、越界连接词、自环、重复、超量一律拒绝
   │
   ├─ 存草稿 ──> draft 表（键：被试 + 教材 + 场次，可反复覆盖）
   │
   └─ 提交 ──> 再校验一次 → submitted 表 → 删除草稿
                            └─ 该 map_version 由此变为 locked
```

契约出口：`contract-share/submission.py` 的 `Submission` / `Draft`。
**本层不产出任何分数**，评分由 `score` 在提交后单独做。

## 无障碍功能
> 含且只含：
> 1. 色盲
> 2. 计算机使用不熟练者

- **色盲**：概念块与连线不使用红/绿区分状态；连线方向用**箭头形状**表达，
  选中态用**加粗描边**而非变色；"已用/未用"零件用实心/虚线两种线型区分。
- **计算机使用不熟练者**：以**点-点连线**为主路径（触摸屏与鼠标一致），
  拖拽作为熟练用户的加速路径；每个按钮文字写明结果（"保存草稿 —— 下次进来接着做"）；
  首次进入给三行图示引导，可关闭且不再打扰；不设双指缩放等隐藏手势。
